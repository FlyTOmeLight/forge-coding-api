# 研发任务与执行契约

浏览器继续使用 `/api/v1/tenants/{tenant}/projects/{project}/tasks` 和 `coding-settings`。同源网关将这些路径转发到 Coding API。所有浏览器请求先通过租户服务的 `/internal/v1/session/check` 验证会话和写请求的 Origin / CSRF，再检查有效项目权限。平台运营身份不隐含代码权限。

任务规则从原 Forge 后端迁入：负责人转交、指定审查者、版本化更新、人工介入、取消、继续、修改要求排队、配置快照、GitLab 行级评论同步、检查结果与人工认可分离。同步评论不会自动发起执行；MR 重开或重新授权不会自动继续任务。

## 业务轮次与运行时

`coding_runs` 保存业务轮次、不可变配置、不可变提交快照及 `runtime_id`。项目配置绑定已发布的 Agent ID 与版本，模型名称仅作为版本摘要显示。Agent 提示词、工具和模型由平台维护；Coding 后端不再生成 Agent 定义。dispatcher 将版本引用、业务上下文和本轮要求提交到 Agentic `POST /internal/v1/executions`，幂等键为业务轮次 ID。网络失败后使用同一快照重试，避免重复执行。运行时记录冻结 tenant/project/actor/task/round 上下文，只有受信任配置身份能使用该入口。

本轮执行快照同时保存任务描述、验收条件、约束和已同步的 GitLab 评论正文、文件位置及对应提交。系统评论不作为审查要求发送给 Agent。仅提交“按评论修改”也能获得实际评论上下文；后续评论更新不改变已提交的运行时快照。

Agentic Worker 独占执行领取、执行租约、步骤恢复与模型决策。原 `/internal/v1/tasks/claim` 已删除。Coding dispatcher 只负责业务提交、权限收紧和状态对账，不另建执行租约。

`agents/coding.json` 使用 `toolsets:["filesystem"]`，Eino 提供文件探索、读取、编辑、写入和 execute。平台在模型启动前准备任务专属 AIO 沙箱并执行基线。同一任务的反馈轮复用沙箱。模型可自行运行诊断命令，调用 run_checks 获取项目检查结果，调用 finish 提交判断。平台冻结候选、独立验收、推送并创建或更新 MR。allowedPaths 限制交付内容；Shell 可生成工作区临时文件。

Worker 注入冻结的 X-Agentic-Scope、runtime ID 与 epoch。Coding 网关校验运行时租约及业务授权，然后注入该任务 AIO 凭据。模型不能指定其他轮次的沙箱。GitLab 凭据仅供平台准备和发布使用。项目管理员选择明确的 Agent 发布版本并复检。

工具开始调用 `/internal/v1/rounds/{round}/start`；写入与检查前调用 `/internal/v1/tasks/{task}/gate`；结果由 `/internal/v1/tasks/{task}/finish` 提交。服务凭据只在后端。业务控制版本、当前项目写权限、运行时执行权都必须有效。交付再次核对 GitLab 当前 commit、分支和 MR 状态，拒绝迟到结果。

## 停止与审查

人工介入在任务事务中先关闭自动写入资格。dispatcher 取消运行时；Coding 网关校验执行资格，dispatcher 删除任务沙箱及本轮活动交付 Pod，确认停止后报告 Stopped。租约过期先停止旧执行者；新 Worker 通过更高 epoch 验证后可接续已保存步骤。仅取消运行时或租约过期不等于业务任务结束或外部进程已停止。未收到确认时保留“停止未确认”，禁止恢复。历史迁入的未知停止状态原样保留。

dispatcher 对活动轮次持续查询权限，每次工具操作也重新检查。授权服务不可用时敏感操作失败关闭。当前控制台轮询业务任务，没有把运行时 SSE 直接暴露给浏览器。运行时自带的 SSE 仍由其服务身份保护。

指定审查者的 `Approve` 要求任务已有 MR、没有活动执行且停止已确认。认可前读取 GitLab 的开放状态、源/目标分支与当前提交；只有 GitLab 确认取消 Draft 后才保存当前提交的人工认可。GitLab 失败不保存认可，提交变化要求先同步后重新审查。重复认可已 Ready 的同一版本不会重复修改 MR。新一轮 `Resume` / `Feedback` / `NextFeedback` 在入队前将已有 MR 恢复 Draft，并清空旧认可。此操作不替代 GitLab 审批规则、流水线、冲突检查或人工合并。

人工处理期间提交正式反馈只保存为待处理要求，不自动恢复 Agent。负责人可以显式选择“恢复并执行这条要求”；服务在同一事务中校验反馈对应的提交、消费反馈并创建新轮次。旧提交的反馈必须先重新核对。运行时进入 NeedsReview 时，dispatcher 立即禁止自动写入并请求工具停止，保留运行时错误，不再等待执行期限到期才显示停止。

edit_file 的 before 未精确匹配时，工具返回已保存的 EDIT_MATCH_FAILED 结果和匹配次数；文件未写入，模型可以重新读取后发起新编辑。该结果作为普通工具反馈保存，不把确定未执行的编辑误判为副作用不明。授权拒绝、执行权失效和不确定的外部操作仍停止执行；Worker 在错误中保留工具名称和受限长度的结构化原因。

已有 MR 且没有新改动时，finish 可以提交当前版本的检查和判断，不产生空提交或重复推送。没有 MR 时仍不创建空 MR。

自动检查 Passed 只表示交付版本检查通过。Agent 判断、人工审查和任务完成分别记录。工具交付保存模型的 Met / Unmet / NeedsHuman 建议；缺少判断时为 NeedsHuman。模型判断不作为人工验收。任务完成依据 GitLab 同步发现的 MR 合入事实。后台 dispatcher 每 5 秒同步尚未结束且已有 MR 的任务，自动导入 MR 合并、关闭、提交和评论变化。页面每 5 秒刷新，正常情况下约 10 秒内可见；不要求浏览器打开或人工点击。手动同步作为立即刷新入口保留。无变化时不增加任务版本或审计事件；单个 MR 同步失败保留当前状态并在下一轮重试，不中断其他任务。已取消和已结束任务不会因 MR 重开而自动恢复。

工具工作目录不包含其他项目的仓库；检查子进程环境不注入服务令牌。当前部署面向可信项目，不能据此声称具备恶意代码隔离。工作卷保存代码和依赖；计算实例在执行权变化时停止并重建。外部操作结果不明时，需核对已有结果，不重复不确定的 Git 写入。

## GitLab 交付链接

任务详情返回 `gitlabUrl` 与 `gitlabTarget`（`mergeRequest`、`branch`、`project`）。已有 MR 时直接链接 MR；没有 MR 时查询 GitLab 的工作分支，确认存在才返回分支链接。分支返回 404 时链接到项目。查询失败返回 `502 GITLAB_BRANCH_UNAVAILABLE`，不能把服务故障当作分支不存在。任务预定了分支名，不代表执行器已把分支推送到 GitLab。

## 切换到发布版本

1. 等待现有自动轮次结束并确认停止。现有业务记录与代码产物保留。
2. 同步升级 Agentic API/Worker、Coding API/工具和前端；旧的内联执行定义不再接受。
3. 编辑 `agents/coding.json` 的模型和工具地址，经 Agentic API 发布。不同项目使用各自获授权的工具部署。
4. 在项目执行配置中选择 Agent 与发布版本，保存并复检。已有未绑定配置会明确要求配置，不能自动生成 Agent 或退回旧执行路径。

此改动完成应用与发布 Agent 的接入。原 agentic-kit 的 Sandbox Manager、Skill、知识资源、Memory 与压缩尚未全部迁移到新运行时，状态以 Agentic API 的迁移清单为准。当前文件和 Shell 工具已接入任务专属 AIO 沙箱。

### 推送后的交付核对

GitLab MR 的 diff 提交信息与源分支 ref 分别读取。finish 使用源分支实时 commit 核对交付版本，并继续核对 MR 的开放状态和源/目标分支，避免 MR 元数据延迟误拒绝刚完成的推送。源分支已被人工更新时仍拒绝交付。工具透传依赖 HTTP 状态及有界的结构化错误 code/message，包含失败接口路径，不再把后端 409 等拒绝统一包装成 503；不返回凭据或原始 HTML 响应。工具不自动重试副作用不明的交付操作。

`read_file.content` 返回原始源码，保留缩进、空行和行尾；行号单独放在 `startLine` / `endLine` 中；`indentation` 给出每行前导空格与 Tab 的实际数量，避免模型从转义文本或展示前缀猜测缩进。`edit_file.before` 必须从最新读取结果逐字复制，并且只匹配一次。匹配失败不写入文件，Agent 需要重新读取后再编辑。修改缩进时，替换块必须包含原始行的前导空白。

仅调整前导缩进时，如果 `after` 已精确存在且只有一个匹配，工具可返回 `unchanged`。这只确认无需写入，不使用模糊匹配改文件。原块在其他位置存在时仍按原块精确替换；多个候选或实际内容不一致仍返回匹配错误。

### 页面代码差异

“代码差异”读取 `GET /api/v1/tenants/{tenant}/projects/{project}/tasks/{task}/diff`，返回当前 GitLab MR 的完整补丁和 base/head/start 提交。后端使用 [GitLab 原始 MR diff 接口](https://docs.gitlab.com/api/merge_requests/#show-merge-request-raw-diffs)，读取前后核对 diff refs 与源/目标分支；版本改变时要求重读。接口校验会话、项目读权限和任务归属，不暴露 GitLab 凭据，不修改任务或 MR。依赖失败和超出 4 MiB 读取上限时返回明确错误，不用历史轮次 patch 代替；没有 MR 时明确返回空差异。页面仅在差异标签打开时随任务刷新，并下载同一份 MR 补丁。单轮 patch 保留在“验证与审查”；空 patch 表示该轮没有新改动，不能视为整个 MR 没有差异。

## 任务沙箱复用

任务沙箱与运行时轮次分开管理。成功交付不会删除任务沙箱。快照与发布期间使用 Linux SIGSTOP/SIGCONT 暂停、恢复容器进程，保留内存状态和 PID；不会把停止工具请求当作后台进程已停止。Kubernetes exec 权限只授予平台，模型 Pod 不挂载 ServiceAccount。

每轮快照使用独立 PVC，模型无法访问候选目录。发布程序重新核对候选与验证目录的文件指纹，然后更新模型工作目录中的受控 Git 元数据。下一轮复用同一 Pod。人工更新源分支时，平台重建计算实例并刷新仓库，保留任务工作卷及仓库外的依赖缓存。工作卷上的准备版本记录由平台维护，不信任模型可修改的标记文件。

任务无活动轮次且闲置 30 分钟、转入人工处理或任务结束时停止计算。回收与反馈入队持有同一个任务锁，避免回收新执行。取消确认仍要求任务 Pod 与活动交付 Pod 真正停止。正常交付的 stopConfirmed 表示本轮 Agent 执行已结束，不表示保留的预览进程已退出。
